# S5-README-UX (sidekick leg), explained plainly

## What changed

A bound fields badge, a hand-authored SVG screenshot of the form (text, not binary — the
estate's zero-binaries law holds), a "What is not asserted" section naming the two honest gaps
(nothing proves a mobile session honors the preamble; template fit is judgment), a de-localized
quickstart, and both README count bindings rewritten first-occurrence → every-occurrence with
planted-conflict controls. The sibling's "six templates" mention was reworded to plain prose so
it cannot collide with the UI's bound four.

## Why

Badges above bound lines are how first-occurrence extractors get retargeted; the rewrite lands
BEFORE the badge by design. The screenshot is SVG because a raster would be the estate's first
tracked binary — declined, disclosed.

## Verify it yourself

```
./scripts/validate-sidekick.sh | grep -E 'every-occurrence|controls fire'
```

## What could break, and what catches it

Badge/prose count drift → named FAIL with both values. A second `**N templates**` claim → the
distinct-values arm fails (which is why the six became prose).
